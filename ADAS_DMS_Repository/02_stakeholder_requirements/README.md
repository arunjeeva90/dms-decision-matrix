# 02 — Stakeholder Requirements

| ID | Requirement | Rationale | Verification | Status |
|---|---|---|---|---|
| STK-DMS-0001 | The platform shall support scalable feature configurations from basic drowsiness warning to driver-aware ADAS fusion. | Reuse across vehicle segments | Inspection | Draft |
| STK-DMS-0002 | The platform shall operate during daytime and night-time cabin conditions using active NIR illumination where required. | 24-hour usability | Vehicle test | Draft |
| STK-DMS-0003 | The platform shall minimize nuisance warnings during sanctioned driving tasks such as mirror, cluster, junction and parking scans. | Driver acceptance | Scenario test | Draft |
| STK-DMS-0004 | The platform shall expose driver state and confidence independently. | Safe downstream fusion | Interface test | Draft |
| STK-DMS-0005 | The platform shall detect and report degraded or unavailable sensing. | Fail-aware behavior | Fault injection | Draft |
| STK-DMS-0006 | The platform shall support India-market cabin diversity including spectacles, sunglasses, facial hair, head coverings, variable skin tones and seating postures. | Regional robustness | Dataset audit + test | Draft |
| STK-DMS-0007 | The platform shall protect cabin imagery and derived personal data throughout collection, storage, service and OTA workflows. | Privacy and cybersecurity | Audit | Draft |
| STK-DMS-0008 | The platform shall provide evidence suitable for OEM safety, SOTIF, cybersecurity and homologation work products. | Production readiness | Work-product review | Draft |
